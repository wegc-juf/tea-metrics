# teametrics v0.13.0

Released 2026-09-04.

## Highlights

- Accelerated daily and CTP processing by resampling only required variables, vectorizing DTEEC calculations, and
  retaining computed Dask results instead of evaluating the daily graph twice.
- Added resource-aware `dask_workers` configuration. Four workers provided the best result for the representative
  Tx30 Austria 2021-2026 benchmark.
- Made `DTEP_GR` deterministic across eager and Dask execution by applying population unit conversion after the
  regional reduction.
- Reduced NetCDF output size by storing spatial floating-point fields as float32 when their value range preserves the
  requested decimal precision. Regional aggregates, coordinates, and unsafe ranges remain float64.
- Renamed `significant_digits` to `rounding_decimal_places` to reflect decimal-place rounding. The old name remains
  available as a deprecated alias for this release.
- Added optional GRIB dependencies, enabled the GitLab test stage, and expanded compression and processing benchmark
  tooling.

## Performance

On the Tx30 Austria 2021-2026 benchmark with zlib disabled, three-run median processing times changed as follows:

| Mode | Previous screening | v0.13.0 | Improvement |
|---|---:|---:|---:|
| Eager | 124.96 s | 94.31 s | 24.5% |
| Auto | 118.74 s | 98.56 s | 17.0% |
| Dask, 4 workers | 324.36 s | 85.27 s | 73.7% |

Peak resident memory was approximately 36.5 GB for eager execution and 32.1 GB for Dask with four workers. The daily
NetCDF output decreased from approximately 19.6 GB to 9.2 GB. Results depend on dataset shape, storage, available
memory, and CPU memory bandwidth.

## Compatibility

- Replace `significant_digits: 3` with `rounding_decimal_places: 3` in configuration files. The deprecated name emits
  a warning and is planned for removal after this release.
- Spatial NetCDF variable dtypes may change from float64 to float32 when this safely preserves the configured decimal
  precision. Code that requires a fixed on-disk dtype should be reviewed.
- `mask_parallel_workers` accepts values from 1 through 100.

## Validation

- Eager and four-worker Dask outputs matched exactly for all variables in the representative daily and CTP outputs.
- Maximum error introduced by safe float32 storage was below 0.000015, within the 0.0005 acceptance tolerance for
  three decimal places.
- The complete automated test suite passes on Python 3.14.
